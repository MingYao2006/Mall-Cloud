## 📊 测试方案四：使用 PowerShell 脚本

创建文件 `test-load-balancer.ps1`：

```powershell
# 测试负载均衡分发效果
$baseUrl = "http://localhost:8082"
$serviceName = "mall-project"
$callCount = 50

Write-Host "开始测试负载均衡..." -ForegroundColor Green
Write-Host "调用次数: $callCount" -ForegroundColor Yellow

# 统计实例分布
$instanceStats = @{}

for ($i = 1; $i -le $callCount; $i++) {
    try {
        $response = Invoke-RestMethod -Uri "$baseUrl/api/lb-test/instance?serviceName=$serviceName" -Method Get
        $instanceKey = "$($response.host):$($response.port)"
        
        if ($instanceStats.ContainsKey($instanceKey)) {
            $instanceStats[$instanceKey]++
        } else {
            $instanceStats[$instanceKey] = 1
        }
        
        Write-Host "第 $i 次调用: $instanceKey" -ForegroundColor Cyan
    } catch {
        Write-Host "第 $i 次调用失败: $($_.Exception.Message)" -ForegroundColor Red
    }
    
    Start-Sleep -Milliseconds 100
}

Write-Host "`n========== 负载均衡统计 ==========" -ForegroundColor Green
$instanceStats.GetEnumerator() | ForEach-Object {
    $percentage = [math]::Round($_.Value / $callCount * 100, 2)
    Write-Host "$($_.Key): $($_.Value) 次 ($percentage%)" -ForegroundColor Yellow
}
Write-Host "=================================" -ForegroundColor Green
```

**运行测试：**
```powershell
.\test-load-balancer.ps1
```

## 📈 预期结果

### 如果负载均衡正常工作：
- **轮询策略（默认）**：每个实例被选中的次数接近均等
  - 3 个实例，100 次调用 → 每个实例约 33-34 次
- **随机策略**：实例被选中的次数随机分布
- **权重策略**：按配置的权重比例分发

### 如果只有一个实例：
- 所有请求都分发到同一个实例
- 需要启动多个实例才能看到负载均衡效果

## 🔍 常见问题排查

### 1. 服务未注册到 Nacos
**检查：**
```powershell
curl http://localhost:8848/nacos/v1/ns/instance/list?serviceName=mall-project
```

**解决：**
- 确保 Nacos 已启动
- 检查 `application.yaml` 中的 Nacos 配置
- 查看应用启动日志是否有注册成功信息

### 2. 只有一个实例
**原因：** 只启动了一个应用实例

**解决：** 按照方案一启动多个实例

### 3. 负载不均衡
**检查负载均衡策略：**
```yaml
spring:
  cloud:
    loadbalancer:
      ribbon:
        enabled: false  # 禁用 Ribbon，使用 Spring Cloud LoadBalancer
```

**自定义负载均衡策略：**
```java
@Configuration
public class LoadBalancerConfig {
    @Bean
    ReactorLoadBalancer<ServiceInstance> randomLoadBalancer(
            Environment environment,
            LoadBalancerClientFactory factory) {
        String name = environment.getProperty(LoadBalancerClientFactory.PROPERTY_NAME);
        return new RandomLoadBalancer(
                factory.getLazyProvider(name, ServiceInstanceListSupplier.class), name);
    }
}
```

## 🎓 负载均衡策略说明

### 1. 轮询策略（Round Robin）- 默认
- 按顺序依次分发请求
- 适用于服务器性能相近的场景

### 2. 随机策略（Random）
- 随机选择服务器
- 长期来看分布均匀

### 3. 加权轮询（Weighted Round Robin）
- 根据服务器性能分配权重
- 性能好的服务器处理更多请求

### 4. 最小连接数（Least Connections）
- 选择当前连接数最少的服务器
- 适用于长连接场景
